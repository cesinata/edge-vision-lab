# Illustration style: Pastel Paper Mono

Public-safe. Commit as `docs/illustration-style.md`. It tells whoever draws or regenerates the README figures what to follow.

## Look

Playful and clear. Soft multi-colour pastel tiles, round dots, no outlines, flat fills only (no gradients, shadows or emoji). Text is monospace. Every figure ships in a light and a dark variant.

## Fonts

SVG files shown in a GitHub README cannot load web fonts. Use this stack in every SVG `font-family`, with no external font files:

`ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas, monospace`

Monospace is wide, so allow for it: body text at least 12 px, titles 16 to 20 px, short labels, and about 20% spare width in every box.

Rules: text and background pairs reach 4.5:1 (large text 3:1); verify with a script and record it in `docs/decisions.md`. Colour never carries meaning alone: pair it with a label or shape. Tiles alternate lilac, mint and butter. Frames and dots are circles. Cards use a 28 px radius, tiles 22 px.

## The five figures

All go in `docs/img/` as `<name>.svg` (light) and `<name>-dark.svg`. Show them in the README with:

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="docs/img/pipeline-dark.svg">
  <img src="docs/img/pipeline.svg" alt="...">
</picture>
```

Every figure needs a `<title>` and `<desc>` inside the SVG and meaningful `alt` text in the README. Hand-made SVGs are written directly. Charts are generated by `scripts/make_figures.py` from `bench/results.json`.

1. **pipeline**: data, split, train, evaluate, quantise, firmware. Six tiles with a one-line caption each. Top of the README.
2. **split-by-scene**: scene clusters feeding train, validation and test, beside a "random frame split leaks" panel. Show cluster counts only if they come from the real split output; otherwise draw the idea with no numbers.
3. **board-data-path**: an original generic board: camera, microcontroller, accelerator, memory, host link. A strip labelled "not measured on hardware". No vendor artwork, logos or photos. Do not trace any datasheet or user-manual figure.
4. **firmware-states**: Mermaid in the README (GitHub draws and themes it), generated from the same state list the C++ tests use. No SVG needed.
5. **results**: a confusion matrix and a float vs int8 size and accuracy chart, generated from `bench/results.json`. Every number carries its label (`measured (host CPU)`). No dataset frames. If a number does not exist yet, the chart shows "not run yet", never a placeholder value.

## What never goes in a figure

Dataset frames or crops, vendor artwork, other people's logos, employer or project names, invented numbers, claims about speed, accuracy or device support that the repo has not measured.
